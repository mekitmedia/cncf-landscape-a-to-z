## Zabbix

**[Homepage](https://www.zabbix.com/)** | **[Repository](https://github.com/zabbix/zabbix)** | **[Documentation](https://www.zabbix.com/documentation/current/en)** | **Status**: non-cncf

An enterprise-class open source distributed monitoring solution designed to monitor and track the performance and availability of network servers, devices, services and other IT resources.

### Key Features
- Real-time monitoring of IT components including networks, servers, VMs, and cloud services
- Highly scalable and capable of monitoring millions of metrics
- Flexible alerting system with custom escalation scenarios
- Native support for high availability and distributed monitoring via Zabbix Proxies

**Latest Release**: [8.0.0beta2](https://github.com/zabbix/zabbix/releases/tag/8.0.0beta2) (2026-07-09)

**Recent Updates**: Recent betas of the upcoming 8.0.0 version focus on performance, UI enhancements, and new integration capabilities for cloud-native environments.

**Use Cases**: Comprehensive IT infrastructure monitoring, network performance tracking, capacity planning, and incident response for large enterprises.

**Interesting Facts**: Zabbix was first released in 2001 and remains entirely open source with no commercial-only features.

**Get Started**: Install Zabbix server, front-end, and agent via official packages, Docker containers, or cloud images. Define hosts to monitor and configure alerting rules.

## Zenko

**[Homepage](https://www.zenko.io)** | **[Repository](https://github.com/scality/zenko)** | **[Documentation](https://documentation.scality.com/zenko/)** | **Status**: non-cncf

An open-source multi-cloud data controller that provides a unified interface for storing, managing, and searching data across multiple cloud storage services and on-premises storage.

### Key Features
- Multi-cloud storage backend support (AWS S3, Azure Blob, Google Cloud Storage, etc.)
- Unified AWS S3 API for transparent data access across heterogeneous environments
- Data management capabilities including replication, lifecycle management, and searching
- Metadata search across stored objects, built on scalable backends

**Latest Release**: [2.15.5](https://github.com/scality/Zenko/releases/tag/2.15.5) (2026-07-31)

**Recent Updates**: Updates to Zenko 2.15.x include Veeam SOSAPI capacity fixes, ZooKeeper tuning, and Kubernetes deployment enhancements.

**Use Cases**: Avoiding vendor lock-in by abstracting storage APIs, implementing hybrid cloud data replication, and unifying object storage management.

**Interesting Facts**: Zenko was developed by Scality and utilizes their robust internal metadata architecture to index multi-cloud objects efficiently.

**Get Started**: Zenko can be deployed on Kubernetes using Helm charts. A basic deployment provides an S3-compatible endpoint to manage underlying storage buckets.

## Zig

**[Homepage](https://ziglang.org/)** | **[Repository](https://github.com/ziglang/zig)** | **[Documentation](https://ziglang.org/documentation/master/)** | **Status**: non-cncf

A general-purpose programming language and toolchain for maintaining robust, optimal, and reusable software.

### Key Features
- No hidden control flow, no hidden memory allocation, no preprocessor, no macros
- A fresh take on error handling based on error values and `catch`/`try` semantics
- First-class support for cross-compiling out-of-the-box
- Can be used as a drop-in C/C++ compiler and seamlessly interacts with C ABI

**Latest Release**: [0.15.1](https://github.com/ziglang/zig/releases/tag/0.15.1) (2025-08-29)

**Recent Updates**: Recent minor releases have focused on improving the standard library, stabilizing the toolchain, and boosting compilation speeds.

**Use Cases**: Writing performant systems-level software, creating WebAssembly modules without bloated runtimes, and building cross-platform tools.

**Interesting Facts**: Zig's build system (`build.zig`) is written in Zig itself, removing the need for tools like CMake or Make, and it famously ships with a bundled C/C++ compiler.

**Get Started**: Download the pre-built binaries from ziglang.org. Write a simple `hello.zig` and run `zig run hello.zig` or `zig build-exe hello.zig`.

## Zipkin

**[Homepage](https://zipkin.io/)** | **[Repository](https://github.com/openzipkin/zipkin)** | **[Documentation](https://zipkin.io/pages/documentation.html)** | **Status**: non-cncf

A distributed tracing system that helps gather timing data needed to troubleshoot latency problems in service architectures.

### Key Features
- Distributed tracing data collection and lookup
- Visual representation of trace data and dependency graphs
- Support for various storage backends including Cassandra, Elasticsearch, and MySQL
- Instrumentation available for popular languages and frameworks

**Latest Release**: [3.6.1](https://github.com/openzipkin/zipkin/releases/tag/3.6.1) (2026-04-08)

**Recent Updates**: Updates include bumping dependencies (like Netty and armeria) and improving Docker image availability.

**Use Cases**: Identifying latency bottlenecks, tracing requests across microservices, and visualizing service dependencies.

**Interesting Facts**: Zipkin was originally developed at Twitter, based on the Google Dapper paper, before becoming an open source project.

**Get Started**: Run Zipkin quickly using Docker: `docker run -d -p 9411:9411 openzipkin/zipkin` and start sending traces using provided instrumentation libraries.

## Zitadel

**[Homepage](https://zitadel.com/)** | **[Repository](https://github.com/zitadel/zitadel)** | **[Documentation](https://zitadel.com/docs)** | **Status**: non-cncf

An open-source identity infrastructure built for the cloud, providing secure authentication, authorization, and user management.

### Key Features
- Multi-tenancy support out-of-the-box, allowing complex B2B and B2C identity structures
- Passwordless authentication and robust MFA options
- Event-sourced architecture providing a complete audit trail of identity changes
- OIDC and SAML 2.0 protocol support

**Latest Release**: [v4.17.3](https://github.com/zitadel/zitadel/releases/tag/v4.17.3) (2026-09-04)

**Recent Updates**: Recent updates (v4.17.x) include cryptographic security enhancements for IDP tokens, improved authorization checks, and better UI translations.

**Use Cases**: Implementing secure login for SaaS platforms, managing decentralized identities across multiple organizations, and enforcing strict IAM policies.

**Interesting Facts**: Zitadel distinguishes itself by being deeply rooted in an event-sourcing paradigm, making its audit capabilities fundamentally different from traditional CRUD-based IAM solutions.

**Get Started**: Run Zitadel via Docker `docker run -p 8080:8080 ghcr.io/zitadel/zitadel:latest` and configure your first tenant via the local UI.

## Zuul

**[Homepage](https://zuul-ci.org)** | **[Repository](https://opendev.org/zuul/zuul)** | **[Documentation](https://zuul-ci.org/docs/zuul/latest/)** | **Status**: non-cncf

A project gating system that drives continuous integration, delivery, and deployment systems with a focus on testing complex, interrelated projects.

### Key Features
- Project gating to ensure broken code never merges into the master branch
- Cross-repository dependencies testing, enabling speculative execution of interrelated changes
- Uses Ansible for build environments, making it highly extensible and declarative
- Natively supports multi-tenant configurations and integration with GitHub, Gerrit, and GitLab

**Latest Release**: [14.2.0](https://opendev.org/zuul/zuul/src/tag/14.2.0) (2026-04-29)

**Recent Updates**: Continued improvements in the v14 series including robust speculative execution capabilities and enhanced multi-tenant system controls.

**Use Cases**: Managing complex CI/CD pipelines across large numbers of repositories, heavily used in large open-source ecosystems like OpenStack.

**Interesting Facts**: Zuul was originally created to manage the massive continuous integration needs of the OpenStack project before becoming a top-level independent project under the OpenInfra Foundation.

**Get Started**: Zuul architecture requires several components (Scheduler, Executor, Web). The recommended approach for testing is using the `zuul-quick-start` docker-compose environment.
